# YUNSH OS v3.1.1

## Display and pointer stability

- Wayland/DRM with Weston Pixman is now the normal Raspberry Pi 5 display
  path. The previous VC4/V3D boot blacklist has been removed so DRM/KMS can
  initialize normally.
- A Qt `linuxfb` session remains only as an explicit recovery path when
  Weston/DRM fails or the Wayland/Qt process repeatedly crashes. It is not
  selected during a healthy boot, and each recovery decision is written to the
  local UI log.
- This addresses the v3.0.4 pointer failure path: the old behavior appeared
  stable because it quickly fell back to linuxfb; v3.1.1 first attempts the
  actual Wayland path with Pixman, which avoids the Weston GL plane assertion.

## Android runtime

- Android setup no longer skips forever when `.android_ready` is stale.
- Binderfs is mounted and checked on every setup attempt, including after a
  reboot with already-downloaded images.
- Image download/init failures remain visible as an error with an explicit
  retry instead of reporting Android as ready.

## Lock and power

- The YUNSH logo remains available on the lock screen. Its lock-screen menu
  exposes restart and shutdown, both behind the normal local confirmation.
- Every normal desktop boot, restart, shutdown, or power-loss recovery writes
  a local boot-lock marker. It is cleared only after a successful local unlock.

## Verification boundary

The source, QML, shell, OTA, boot configuration, and image structure checks
are run before release. Real Pi 5 display, Android image download, mouse, and
power-cycle behavior still require the target hardware; those results are
reported separately from static checks.
