# YUNSH OS v3.0.4

YUNSH OS v3.0.4 adds a complete Chinese-input switching path to the existing
Fcitx5/Pinyin packages and advances the OTA version so v3.0.3 devices can
receive it normally.

## Highlights

- The first-boot image includes Fcitx5, `fcitx5-chinese-addons`, the Qt 6
  frontend, Noto CJK fonts and color emoji fonts. The launcher writes a stable
  keyboard-us/Pinyin profile before starting the graphical session.
- Clicking the YUNSH logo opens a new Input Method tile in the system menu.
  It switches between `ABC` and `中` and changes the active Fcitx5 method.
- The spatial keyboard has a Mac-style globe key at the left side of the space
  row. It uses the same switch as the YUNSH menu and shows `🌐`/`中` state.
- In Pinyin mode, virtual letters and editing keys are sent as physical-style
  Linux input events through the local uinput bridge, allowing Fcitx5 to show
  Chinese candidates instead of merely inserting Latin letters into QML.
- Minimized windows remain in the swipe-up App Switcher. Cards show whether an
  app is running in the background and remain directly tappable to restore it,
  with a close control kept above the card hit area.
- Android preparation now reports a stopped setup service or a stale download
  as an actionable error instead of leaving the screen on “preparing” forever;
  the Android page exposes a retry action without blocking the YUNSH desktop.
- The release version is `v3.0.4`; the OTA manifest and installed version file
  therefore pass the normal newer-version check from v3.0.3.

## Validation boundary

The source is checked with QML, Python and shell validation, then rebuilt with
the protected Raspberry Pi 5 firmware layer, image/rootfs checks, OTA manifest
checks and the non-writing macOS flasher check. Actual Pinyin candidate display
and hardware uinput delivery still require testing on the Raspberry Pi 5 with
the target display and a focused input field.
