# YUNSH OS v4.2

v4.2 keeps the v4.x Raspberry Pi 5 boot and OTA baseline and fixes the
preloaded Waydroid runtime readiness check.

## Android runtime fix

- Preloaded arm64 `system.img` and `vendor.img` remain in the image's
  dedicated Waydroid preload directory; the runtime configuration records that
  directory in `waydroid.cfg`.
- Readiness now follows Waydroid's configured `images_path` and requires the
  configuration, rootfs, and both image files. It no longer incorrectly
  requires a second copy under `/var/lib/waydroid/images`.
- A stale or partial initialization is retried safely. The Android panel shows
  the actual missing runtime component instead of the misleading generic
  configuration error.
- Android remains a non-blocking background service. The desktop can start even
  when Wayland, binder, networking, or Android initialization is unavailable.

## Display and update baseline

- Raspberry Pi 5 KMS/Wayland remains the default display path.
- framebuffer/linuxfb remains an explicit recovery path only; EDID/HPD select
  the display mode and no fixed 1080p timing is added.
- `4.1 → 4.2` uses the checksum-verified manifest/content-chunk delta OTA path. Full-image
  flashing remains required when the Pi 5 boot firmware or kernel ABI is not
  already the validated baseline.

## Verification boundary

The v4.2 image is checked for the Pi 5 firmware layer, matching
`6.18.39+rpt-rpi-2712` ABI, XZ/SHA-256 integrity, rootfs/ext4 structure,
Waydroid preload assets, Android initialization logic, OTA reconstruction, and
the non-writing desktop flasher check. Raspberry Pi 5 display, Android GPU/
Wayland behavior, Bluetooth, input peripherals, and the final SD-card cold boot
remain hardware tests for this exact v4.2 image.
