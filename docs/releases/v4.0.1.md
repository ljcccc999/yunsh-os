# YUNSH OS v4.0.1

v4.0.1 is a small legacy OTA bridge between the v4.0 updater and the v4.1
delta OTA system.

- v4.0 devices install this release using the existing `yunsh-ota-v1`
  archive format.
- The bridge updates the OTA updater, update daemon, services, and user-space
  files; it does not rewrite the boot partition or kernel firmware.
- After rebooting into v4.0.1, the device can download the v4.1 manifest and
  only the changed content chunks.
- The bridge carries the same user-space fixes as v4.0/v4.1: single-surface
  first-boot progress with monotonic real download detail, network recovery,
  Chinese pinyin input handling, browser download/new-tab behavior, Finder-like
  Files layout, rounded Screen Relay corners, background-window retention, and
  non-blocking Android/OpenXR/media preparation.
- A full image remains necessary when the installed Pi 5 boot firmware,
  kernel/initramfs/DTB/overlay, or `/lib/modules` ABI is not already the
  validated baseline.

## 2026-08-13 local bridge verification

- Legacy bridge SHA-256: `bc6881b7dfea71dbadcf5855067837cd1142da9147be3697c1b48f0dbff5eaed`
- The updater installs 149 user-space files from the archive; it contains no
  boot-partition payload.
- A staged-root install test upgraded `4.0 → 4.0.1` successfully. A separate
  HTTP Range test then verified `4.0.1 → 4.1`: 151 chunks on the first run,
  zero on the second, and one after changing one local file.
- These are local updater tests, not Raspberry Pi 5 hardware tests.
- The bridge deliberately does not change boot `cmdline.txt`; a device that
  needs the framebuffer boot fix must use the rebuilt full Pi 5 image. Once
  the bridge has installed the new updater, the v4.1 delta manifest includes
  the matching user-space `display.conf` policy.
