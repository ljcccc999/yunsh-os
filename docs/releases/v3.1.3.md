# YUNSH OS v3.1.3

v3.1.3 fixes the firstboot handoff that could show installation progress,
reboot, and then leave a live kernel with a black display and no SSH service.

## Startup and firstboot

- Firstboot now keeps `.packages_installed` absent until the package groups,
  SSH service, Qt QML runtime, Weston, and the desktop service enablement have
  passed a reboot-handoff validation.
- A failed validation exits without rebooting, preserves the firstboot and
  APT logs, and lets systemd retry the installation instead of silently
  declaring success.
- A post-reboot `yunsh-boot-health.service` independently verifies SSH and
  desktop service state and records `yunsh-ui.log`/`yunsh-weston.log` when the
  graphical launcher fails.
- The download view continues to show real `MB / total MB` values, while
  unpacking and configuration remain separate states.

## Verification

- XZ integrity, SHA-256, Pi 5 boot partition, cmdline, ext4, required files,
  and clean firstboot markers passed.
- A clean ARM64 generic-virt run completed package installation, crossed the
  former 42% area, passed reboot-handoff validation, wrote the marker, and
  rebooted automatically.
- After reboot, the VM reported active SSH, active health guard, and an
  enabled YUNSH desktop service. Generic virt has no Raspberry Pi 5 DRM/fb
  scanout, so no real Pi 5 display result is claimed.
