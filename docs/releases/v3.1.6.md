# YUNSH OS v3.1.6

v3.1.6 is a Pi 5 boot, graphics, input, background-app, OTA, and Android
reliability release. The image builder now rejects a boot firmware layer whose
kernel/initramfs ABI does not match the clean root filesystem modules. When the
archived layer is newer than the base image, the build keeps Raspberry Pi OS's
internally matched Pi 5 kernel, initramfs, DTBs, overlays, and modules instead
of producing a system that boots but cannot load KMS, Wi-Fi, or other drivers.

The primary display path remains Pi 5 KMS, DRM, and Wayland. A framebuffer
recovery path is available only after a diagnosed primary-path failure and the
trigger is recorded. Normal boots do not blacklist VC4/V3D or expose detailed
system startup logs on the optical display.

First boot preserves the live NetworkManager process while packages are still
being downloaded instead of restarting the network stack near the former 42%
handoff point. Download, unpack, and configuration are shown as distinct
stages, with real downloaded MB / total MB whenever APT provides a total.

The spatial keyboard now keeps one stable uinput device for Fcitx Pinyin so a
composition is not reset between letters. Background restoration includes
dynamic Android windows and the complete saved workspace set. Android setup
checks free space, allows slow image downloads to finish, continually updates
its activity state, and never blocks the desktop. OTA accepts an active Wi-Fi
or Ethernet connection and reports downloaded MB when the total is known.

Static QML, Python, shell, filesystem, image, and boot-stack validation passed.
A clean generic ARM64 VM completed all first-boot package stages, crossed the
network handoff, wrote the completed-package marker, and rebooted. Raspberry
Pi 5 display, Bluetooth audio, Android, and physical input behavior remain
hardware-validation items until this image is freshly written and booted on
the target device.
