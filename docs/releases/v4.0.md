# YUNSH OS v4.0

v4.0 carries forward the confirmed stability fixes from v3.1.0 and v3.1.3,
the first-boot and recovery fixes from v3.1.6, and the confirmed Raspberry Pi
5 boot firmware layer.

## Fixed release foundation

- The default build target is Raspberry Pi 5.
- Builds use the complete dedicated firmware directory at
  `启动固件层/Raspberry Pi 5`, including the firmware payload, Pi 5 kernel,
  initramfs, DTBs, and overlays.
- The required kernel ABI is pinned to
  `6.18.39+rpt-rpi-2712`. A mismatched base rootfs is rejected; the builder
  never falls back to an older kernel or silently creates an ABI-mixed image.
- `config.txt` retains the Pi 5 hardware overlay `dtoverlay=vc4-kms-v3d-pi5`
  and removes `disable_fw_kms_setup=1`. KMS/Wayland is the release default so
  Android has a real graphics session; only the explicit linuxfb recovery
  build adds `module_blacklist=vc4,v3d` to preserve firmware simplefb when a
  target cannot create DRM. EDID/HPD still choose the display mode. No fixed
  1080p mode or HDMI timing is written. The generic VC4 overlay and the
  v3.1.6 KMS regression are rejected by the final boot-partition check.

## First-boot stability

- Downloads show real `MB / total MB` values when APT provides a total, while
  unpacking and configuration remain separate stages.
- APT transactions have bounded timeouts, retry and repair handling, and do
  not require a power cycle to recover a stalled package operation.
- An active NetworkManager connection is kept alive while packages are being
  downloaded. NetworkManager is started only when it is inactive, and
  recovery is attempted only after a real connection failure.
- `.packages_installed` is written only after package installation, SSH,
  Weston, Qt QML, and the desktop service pass the reboot-handoff check.
- The post-reboot health guard preserves SSH and desktop diagnostics without
  making optional Android, OpenXR, media, or voice preparation a desktop
  startup dependency.

## Verification boundary

The source and build gates verify the Pi 5 firmware directory, ABI, retained
KMS overlay, dynamic framebuffer boot arguments, first-boot scripts, systemd
desktop dependencies, ext4 structure, and image integrity. A fresh v4.0 image
still requires a separately recorded Raspberry Pi 5 SD-card/display/USB/network
hardware test; QEMU and static checks do not replace that test.
