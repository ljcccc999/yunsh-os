# YUNSH OS v4.1

v4.1 introduces the first YUNSH OS delta OTA format. The device downloads a
small checksum-verified manifest, compares the target file and content-chunk hashes with
the installed system, and requests only missing or changed chunks from the
release chunk store using HTTP byte ranges.

## OTA model

- Same-major updates may skip intermediate minor releases, for example
  `4.1 → 4.3`.
- Cross-major updates are reserved for an explicit adjacent-major bridge and
  may not skip a major version, for example `4.x → 5.x` is possible with a
  bridge manifest while `4.x → 6.x` is rejected.
- The updater validates the compatibility range before downloading chunks,
  verifies every chunk and reconstructed file, stages changed files, and keeps
  a rollback backup before replacement.
- The 4.0 updater does not understand the delta format. The small 4.0.1
  legacy bridge OTA upgrades only the updater and user-space services; after
  rebooting into 4.0.1, the device can receive the v4.1 delta OTA. A full
  image is still required if the device's boot firmware, kernel, initramfs,
  DTB, overlay, or module ABI is not already the validated Pi 5 baseline.

## Verification boundary

The delta manifest and chunk store pass local SHA-256, Python, shell, and
range-download tests. A clean installation test reconstructed all target files;
a second run downloaded zero chunks, and a deliberately changed local file
downloaded only the required replacement data. Raspberry Pi 5 boot, display,
network, and peripheral validation remains separate from these local tests.

The full image retains `vc4-kms-v3d-pi5` as the Pi 5 hardware overlay and
defaults to KMS/Wayland so Android has a real graphics session. If KMS cannot
create a DRM device, the launcher keeps an explicit linuxfb recovery path;
that path may be built with `module_blacklist=vc4,v3d` to preserve firmware
simplefb. Display mode selection remains EDID/HPD-driven; the image does not
force 1080p or write fixed HDMI timings. The delta payload also carries
`/etc/yunsh/display.conf` so the user-space display policy stays aligned after
`4.0.1 → 4.1`.
