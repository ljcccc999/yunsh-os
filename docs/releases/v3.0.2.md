# YUNSH OS v3.0.2

YUNSH OS v3.0.2 refines the relationship between the spatial desktop and
application windows while improving optical-display legibility.

## Highlights

- The desktop application icon shelf now recedes automatically whenever an
  application window opens, reducing visual competition behind active work.
- The circular launcher now matches its documented 13-app, 4–5–4 spatial
  arrangement on each automatically paginated screen.
- With an application window visible, selecting exposed desktop background
  toggles the temporary icon shelf. Restoring it starts a 30-second inactivity
  timer; opening an app hides it immediately, and changing icon pages resets
  the timer.
- The top-left YUNSH system menu includes an explicit application-icon tile
  for showing or persistently hiding the shelf. A manual hide choice is not
  cancelled by clicking empty desktop space and is retained as a device
  preference. The existing automatic lock interval now follows the same
  validated preference persistence path.
- Minimizing a window, closing the final tracked application, returning Home,
  and restoring a SpaceCapsule all resolve to a predictable icon-shelf state.
- The shared application-window material is slightly more opaque, improving
  text and control stability on transparent AR optics without becoming solid.
- Visible system surfaces now share one bright liquid-glass language across
  activation, application windows, menus, task switching, the keyboard,
  dialogs, browser chrome, terminal chrome, and recovery UI.
- Optical black remains reserved for transparent AR canvas, dimming layers,
  calibration space, and media content. Bright glass uses dark text where it
  produces the stronger readable contrast.
- The interaction pass follows spatial-design principles from visionOS —
  stable system access, responsive hover feedback, restrained depth, and
  legible translucent materials — while retaining YUNSH's own layout and AR
  optical constraints.
- The optical display no longer acts as the local boot-log console. Startup
  diagnostics remain in the journal and on `serial0`, while tty1 is reserved
  for the YUNSH splash and desktop. The splash is also available during the
  first installation phase.
- Raspberry Pi 5 firmware, kernel, initramfs, DTB, overlay, partition, and
  hardware configuration inputs remain based on the protected confirmed boot
  firmware layer; only the generated quiet-boot command line and YUNSH runtime
  content change in this release.

## Validation

This release was checked through incremental QML, Python, and shell static
validation, image construction and structural inspection, boot/rootfs
embedded-file and systemd-link checks, XZ/SHA-256 verification, OTA manifest
inspection, and the macOS flasher's non-writing `--check` mode.

The final archive matches the protected tested baseline's partition layout,
hardware `config.txt`, and all 420 confirmed Raspberry Pi 5 firmware-layer
hashes. All 20 YUNSH service enable links, four known blocking stock-service
masks, and all 138 OTA/rootfs payload hashes were also verified.

No virtual-machine boot was run for this update. This exact archive was also
not reflashed to a Raspberry Pi 5, so earlier framebuffer and BLE evidence is
not presented as v3.0.2 hardware validation. Real Pi 5 startup, display,
motion hardware, Android, microphone, and optical interaction remain hardware
validation boundaries.
